# 闱墨题库制作

把考试大纲、教材、笔记或用户需求，转成闱墨可直接导入的高质量题库文件。**不要只输出题目文本**；最终交付必须是可导入文件、校验报告和简短说明。

## 何时使用

- 用户要 AI 生成一套新题库，或扩展现有题库。
- 用户要把 PDF/Word/Markdown/表格资料整理成可导入题库。
- 用户已有题目，需要补解析、知识点、标签、难度或统一格式。
- 用户要设计组卷蓝图、题型配比、章节覆盖。
- 用户要校验/修复闱墨 CSV、Excel 或 JSON 导入文件。

## 先问清楚

缺少以下信息时，先问最关键的 1–3 项，不要自行假设考试范围：

1. 考试/学科、目标人群、教材或大纲版本。
2. 题目数量、题型配比、难度分布、语言。
3. 输出格式：CSV（默认）、Excel 或 JSON。
4. 是否允许改写已有题目；版权/来源限制。
5. 题库结构：一级题库、子库/章节、知识点命名。

用户说“随便”时，按“考试名称 → 2–4 个一级题库 → 每库 2–5 个子库”给出合理蓝图，并在交付时说明假设。

## 工作流

1. **设计蓝图**：先列出大题库/子库、知识点、题型和难度配比；控制在用户要求的数量，不靠重复题凑数。
2. **分批出题**：每批 10–20 题，先完成一个子库，再进入下一个；保持术语、答案格式、解析风格一致。
3. **写导入文件**：严格按下方字段和答案格式；CSV 一行一题，单元格内不得换行。
4. **机器校验**：运行 `node scripts/validate-bank.mjs <文件> --strict`，修复所有错误；警告也要逐条判断。
5. **人工抽检**：检查答案唯一性、干扰项质量、解析是否解释“为什么对/为什么错”、是否有重复或事实错误。
6. **交付**：输出文件、蓝图、校验摘要、导入步骤。不要粘贴整份题库到聊天里替代文件。

## 硬性格式

CSV 表头必须包含（顺序可变）：

```csv
大题库,小题库,题型,题干,选项A,选项B,选项C,选项D,答案,可接受答案,解析,知识点,标签,难度,来源,排序号
```

字段规则：

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 大题库 | 是 | 一级题库名；不能为空。留空时应用会归入“导入题库”，但 AI 不应依赖该兜底 |
| 小题库 | 否 | 章节/子库；必须在所属大题库下保持同名同层 |
| 题型 | 是 | 只能是 `单选` / `多选` / `判断` / `填空`（也接受 single/multiple/judge/fill） |
| 题干 | 是 | 单行纯文本；填空用连续两个以上下划线 `____` 表示一个空 |
| 选项A–H | 选择题必填 | 单选/多选至少 A、B 两个，建议连续填写；判断/填空留空 |
| 答案 | 是 | 见下方“答案规则” |
| 可接受答案 | 填空建议 | 每空一组，组内用 `\|` 分隔等价答案，组间用 `;` 分隔 |
| 解析 | 建议 | 说明正确答案依据，并指出典型错误项；不要只写“见教材” |
| 知识点 | 建议 | 多个用 `;`、`，`、`、` 或 `\|` 分隔；建议 1–3 个 |
| 标签 | 否 | 多个用 `;` 分隔；用于筛选和检索 |
| 难度 | 否 | 1–5 的整数；缺省按 2 处理 |
| 来源 | 否 | 真题年份、教材页码、原创/改编说明 |
| 排序号 | 否 | 数字；缺省按导入顺序 |

字段别名（应用兼容）：`章节`=小题库，`题目`=题干，`考点`=知识点，`analysis`=解析，`correctAnswer`=答案。AI 输出时统一使用上面的中文标准表头。

## 答案规则

```text
单选：B
多选：A,C,D       # 必须用逗号/顿号分隔；不要写 ABD
判断：对 / 错 / 正确 / 错误 / true / false / √ / ×
填空：第一空答案;第二空答案
```

- 单选必须恰好一个选项键；多选至少两个选项键。
- 答案键必须存在于该题选项中；选项键按 A–H 顺序。
- 填空答案个数要与题干空格数一致；每个空一个答案，用 `;` 分隔。
- 填空题等价答案：`答案1|别名1;答案2|别名2`；组数必须与答案数一致。
- 判断题统一写 `对` 或 `错`；应用也接受 `正确/错误/true/false/√/×` 等写法，但同一套题里要保持风格一致。
- 题干、选项、解析中避免用英文逗号分隔多个答案；CSV 中含逗号/引号的单元格必须用双引号包裹，并把内部双引号写成 `""`。

## CSV 兼容性（重要）

闱墨当前的 CSV 解析器**按行读取**，不支持单元格内换行。因此：

- 一题必须在一行内；解析需要分段时用 `；`、` / ` 或句号，不要按回车。
- 含逗号的题干/选项/解析必须加双引号。
- 使用 UTF-8；带不带 BOM 都可，带 BOM 对 Excel 更友好。
- Excel 同样按行解析；如果单元格内有换行，请先替换为单行文本再导入。
- 不要把 Markdown 表格直接改后缀当作 CSV；必须输出真实逗号分隔文件。

JSON 可选格式（适合程序生成）：

```json
[
  {
    "大题库": "初中生物",
    "小题库": "光合作用",
    "题型": "单选",
    "题干": "光合作用主要发生在植物细胞的哪个结构中？",
    "选项A": "线粒体",
    "选项B": "叶绿体",
    "选项C": "细胞核",
    "选项D": "液泡",
    "答案": "B",
    "解析": "叶绿体含有叶绿素，是光合作用的主要场所。",
    "知识点": "光合作用;细胞结构",
    "难度": 2,
    "来源": "原创"
  }
]
```

也可以输出 `{ "questions": [ ... ] }`。**不要输出带 `banks` 与 `questions` 的完整备份结构**；那会被应用识别为整库恢复，覆盖用户数据。

## 质量门槛

- **一题一义**：题干只问一件事；单选只有一个无争议正确答案。
- **干扰项像真的**：同类别、同粒度、长度相近；避免“以上都对/都不对”凑数。
- **解析有用**：至少说明正确依据；选择题指出关键错误项错在哪里。
- **不重复**：题干+选项+答案相同即重复；同一知识点不要连续出同质题。
- **难度有梯度**：一套题里 1–2 星、3 星、4–5 星都要有，按用户要求调整。
- **覆盖有结构**：每个子库/知识点都有题；不要只堆一个章节。
- **来源诚实**：原创写“原创/改编”；引用真题标明来源；不要编造年份、出版方或页码。
- **版权**：不要大段复制受版权保护的真题/教材；需要时改写并注明“改编”，或让用户提供有权使用的材料。

## 校验

在本 skill 目录运行：

```bash
node scripts/validate-bank.mjs examples/sample-bank.csv --strict
node scripts/validate-bank.mjs 你的题库.csv --json
```

- 退出码 0 才表示可交付；有错误时按报告逐行修复。
- `--strict` 会把“解析为空/知识点为空/选项不连续”等警告也视为失败，适合正式交付。
- 校验通过后，仍要人工抽检 10%–20% 的题目；机器只能查格式，不能保证学科正确性。

## 交付格式

每次交付至少包含：

1. 题库文件路径（`.csv` / `.xlsx` / `.json`）。
2. 蓝图摘要：大题库/子库/知识点、题型与难度分布。
3. 校验摘要：总题数、各题型数量、错误/警告、是否通过 `--strict`。
4. 导入步骤：闱墨 → 题库 → 导入题库 → 选择文件 → 检查导入报告。
5. 已知限制：例如“本批为原创示例题，未覆盖实验题”。
